# v0.11.0 独立使用与恢复验收

本次面向新用户缩短首次建档、分析和维护流程，保留原有本地数据库与连接器接口，没有新增业务数据表。

- 可选 BOSS：默认不启动、不猜测路径。桌面原生桥保存本机配置并显式启动；浏览器提供可行的手工建档退路。
- 首次建档：企业、岗位名称、完整 JD 三项必填，复用原有事务化导入与判重。相同来源的新 JD 进入人工审核，不丢弃新原文。
- 分析：岗位提取包内置指令，任务页展示范围、进度、下一步及预计产物。统一导回 JD 要求后留在对应批次审核，格式错误给出修复方法。
- 数据：完整 ZIP 是默认备份入口，JSON 仅称为导出。图形化恢复只存在于桌面原生桥，网页没有替换数据库的 HTTP 接口。
- 恢复：选中文件先复制到独立暂存目录，拒绝重复 ZIP 路径、超限展开、缺失截图或未来 schema。确认后封闭 HTTP 服务，等请求结束，二次检查采集任务，再保存当前完整 ZIP。替换数据库和附件的过程有回退日志；失败回退，进程中断后下次启动回退。成功后释放单实例锁并重启。
- 升级：迁移前备份旧数据库和引用附件；拒绝用旧程序降级新数据库。已有离线恢复 CLI 继续兼容。
- 诊断：导出应用/系统版本、schema/完整性状态和最多 30 条错误时间、级别；不导出日志消息、用户名路径、岗位、联系人或凭据。

## 自动化验收

`tests/test_independent_desktop.py` 使用临时数据库验证恢复前预览不修改数据、确认后的原始备份可恢复、文件锁失败回退、意外中断回退、截图与版本校验、升级备份、无 WSL 的缺省配置、原生桥停止服务后才替换并重启、诊断脱敏与快速建档。

`tools/check_daily_flow.cjs` 使用真实 Chromium 验证三字段建档、原有岗位与采集流程、浏览器恢复禁用，以及原生桥协议的配置、预览与明确确认。原生文件替换由上述 Python 控制器测试独立验证。

PR 工作流与 Windows EXE 发布工作流安装 Chromium 并设置 `RADAR_REQUIRE_BROWSER=1`，缺失依赖不再跳过。打包后的 `--self-test` 额外执行隔离目录的完整备份恢复，要求 `recovery` 与 `optional_connector` 为 true。

这些检查不替代不同用户设备上的真实 WebView2 窗口验收，也不验证招聘平台当前账号登录和在线采集。对外分发前仍应在无开发环境的 Windows 设备上完成一次人工首次启动、升级及恢复验收。
