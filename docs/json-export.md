# JSON/ZIP 一键导出（P0）

## UI 与选择范围

- 岗位库和企业观察库都有「导出 JSON」按钮。
- 导出对象严格等于当前页面的筛选结果，分别由前端复用的 `selectedJobs()`、`selectedCompanies()` 决定。
- 岗位筛选包括关键词、方向、核验状态、关注优先级、城市、企业行业与人数范围。
- 企业筛选包括关键词、行业、人数范围及是否包含规模待录入企业。无匹配结果时按钮不可用。
- 浏览器将当前结果的正整数 ID 数组和筛选元数据发给后端。后端核对全部 ID：删除/不存在时明确返回 422，不静默漏行。

## 数据与格式

API：`POST /api/exports/jobs`、`POST /api/exports/companies`，请求：
```json
{"ids":[1,2,3],"filters":{"headcount_min":"100","headcount_max":"1000","include_unknown_size":"true","q":"产品"}}
```

- 单批次响应为 `application/json` 文件；多批为 `application/zip`，内含 `manifest.json` 与编号 JSON。
- 根据 UTF-8 字节量和条数共同拆分，目标每批不超过 50 条、约 350KB；既有 250 条和 3MB 约束仍是每个岗位分析包的硬性安全边界。
- manifest 记录导出 ID、筛选参数、总记录数、每批文件名、记录 ID、数量及 SHA-256；单批次文件的 `export_metadata` 保留同样的批次来源信息。
- 同一操作在 SQLite 事务内读取；岗位读取与快照保存同时完成，不跨多次 HTTP 请求抓取不同时间的数据。
- 不截断 JD 或企业观察记录；若单条记录超限，返回错误并中止导出。

### 岗位导出

- `schema=ai-internship-radar-analysis-v1`，保留 `package_id` 和现有 `jobs` 等字段，用原分析工作台的 JSON 导回格式继续提交 `findings`。
- 完整保留职位、资格条件、完整 JD、来源、技能及已有公司观察。`company_profile` 包含 `headcount_min`、`headcount_max`、`headcount_text`、`headcount_source_url`、`headcount_observed_on`，不再导出旧分类字段。
- `analysis_packages` 中仅存本批关联 ID 和原始数据的哈希快照，不复制整个 JD；既有旧版分析包仍使用旧格式，未修改它们的解释方式。
- 默认排除岗位个人备注、投递沟通、简历版本、我的能力与经历。

### 企业导出

- `schema=ai-internship-radar-company-export-v1`，包含企业 ID、名称、行业、人数区间与来源、城市、官网、现有状态、关联岗位数量、高优先级数量、岗位摘要及原始观察记录。
- 不带岗位 JD，不包含企业自由文本私密备注或联系人。当前企业表没有独立的经核实 `intro` 字段，暂时不把 `notes` 当成公共简介输出。
- 企业导出数据包不支持直接粘贴进现有仅针对岗位 `findings` 的导回接口；企业分析导回属于后续阶段。

## 数据可信度和安全边界

1. 企业规模保留人数区间原文与来源；缺失时保持空值，不推算精确人数。
2. 招聘状态、核验状态和岗位评分均来自既有数据库记录，不因导出被改变。
3. 所有数据本地生成，需要用户自己交给 AI 助手；JD 和观察记录不可信，不是系统指令。
4. 导出的文件包含真实企业和招聘内容，尤其公司观察记录可能含自由文本；**在外部上传前仍需人工检查文件**。
5. 一次最多请求 10,000 个不同 ID；全部 ID 必须存在。空选择拒绝导出。
