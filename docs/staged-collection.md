## 用户流程

实习僧采集页新增三种操作：

1. **发现岗位并读取详情**：先读取受限数量的列表页，按来源 ID 汇总全部命中，再读取获额度的详情。
2. **仅发现列表岗位**：只保存链接、可可靠读取的列表字段与命中记录，不读取 JD，也不把列表摘要当作完整岗位说明入库。
3. **补齐未读详情**：列表候选面板显示本批次待处理数量；点击按钮，预览并确认后只访问这些岗位详情，不重复搜索列表。

详情额度不足、暂停或失败时，已发现的身份与原始链接保留。重开桌面、恢复数据库后仍可补齐这些候选。运行期间不能重复启动同平台采集。未读取的列表页目前通过新一轮规划检索，尚无自动页游标恢复。

取得的详情继续进入现有收件箱，人工核对后入库；城市缺失保持未知，不填成搜索城市。无可靠标题/企业字段的候选保留为待补齐，不生成虚构资料。来源明确下线或已知城市不匹配会记录筛除状态；这些访问也计入成本。

## 缓存与岗位身份

同平台＋来源 ID 形成独立身份；不同搜索词、城市与页码的命中全部保留。本轮同一身份只读取一次详情。

默认复用 24 小时内、当前解析版本下的完整详情。缓存种子最多 60 条，未命中缓存的候选仍受详情预算约束；超过缓存种子范围不等于来源过期。勾选「重新读取详情（不复用缓存）」可以主动核验。默认时效是首期规则，不能证明资料仍在招聘；尚无自动抽样核验或个人目标驱动的新鲜度调度。

最后列表发现、最后真实详情读取分别记录。缓存再次命中不把旧 JD 变成刚读取的新 JD。相同内容复读只更新读取时间，内容字段变化才形成新版本；缓存复用不覆盖新版本。不同平台的开放状态和需求关联尚不自动合并。

## 成本与执行额度

面板分别显示列表访问尝试、详情访问尝试、缓存复用和待核对访问。连接器在导航前持久化回执，导航完成或失败后结算；等待中取消不会当作发起访问。已发出但结果未知的请求保留成本，不能当作零收益或退还预算。

从保存计划准备的实习僧批次遵守快照中的查询身份及每项列表/详情总额度。启动前在同一数据库事务中核对并预留额度；预览和启动都会再次核对，以启动时剩余额度为准。一次任务结束且回执完整时，未用额度可继续用于同一动作的后续补全。页面参数超出剩余额度会被后端收窄，确认页展示实际值；篡改计划批次的关键词/城市不能绕过额度。

列表发现不占用详情额度；详情续补不占用列表额度。每项原分配额度相加不超过计划总量，首期不在不同动作之间自动重新分配余量。缓存命中不消耗平台详情访问次数，但仍受候选与快照大小限制。

实习僧计划还记录各轮执行耗时；剩余时间用尽后不启动新动作。截止时间会传给连接器，活动访问按有限超时结束，不能保证恰好在截止时刻立即取消。人工审核等待时间不计为一次采集的执行耗时。

崩溃或旧版本任务没有完整回执时，保留其预留额度；旧任务缺少预留信息时，保守保留该动作原分配额度，不默认为零。界面明确标注历史成本未核实。此时需核对已有结果；继续探索可显式建立新计划，不能静默重置旧计划预算。

BOSS 保持现有采集路径，不宣称有严格详情访问计数或计划累计成本保障。普通手工批次仍使用本次任务上限；人工在外部浏览器打开链接的访问不属于连接器回执。计划仍需逐条确认，尚无自动连续执行或完整计划级暂停队列。

## 检查记录

- 完整后端测试 195 项通过；最后的列表字段长度边界修复后，存储/执行预算 18 项复查通过（含新增边界用例）。Node 连接器 18 项测试通过，UI 模拟检查通过。

- 浏览器使用真实本地 API 和隔离数据库，平台就绪响应为模拟：2 条列表候选、1 次列表访问、0 次详情访问，未读 JD 不入核对队列；补齐确认不访问列表，计划详情限额收窄为 4 次；重新加载仍保留 2 条待办，无页面脚本错误。
- 连接器的模拟浏览器检查覆盖同义词命中汇总、先列表后详情、仅发现、缓存命中零详情访问且不启动浏览器、失败/下线计费、未知城市、停止及时间额度。没有为本轮验证新增真实平台访问，因此不能据此宣称真实召回率或节省比例。
- 用户数据库通过只读快照迁移到 schema11，原 2 个批次及 15 条资料保留，完整性及外键检查通过；用户数据库未被检查程序改写。

本轮用户流程回顾：待补齐候选与取得 JD 的核对队列分开展示，避免误认为列表摘要已完整采集；确认页展示服务器收窄后的额度，并明确续补不重新搜索列表。历史任务缺回执、读取时间与缓存时间分别显示，减少错误理解。后续仍应补齐列表页恢复队列和完整的 JD 版本对比界面，计划自动推进需基于本轮成本与身份基础实现。
