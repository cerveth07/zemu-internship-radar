# 关键词与检索规划 · v0.9.0

v0.10.0 的实习僧计划执行额度、分段采集和缓存能力见 [分段采集与缓存](staged-collection.md)；下文保留首期导入与规划操作说明。

## 如何使用

1. 打开桌面左侧「关键词与检索规划」→「导入词库」。
2. 点击「加载 V1 岗位词库」，或上传/粘贴 JSON、CSV、Markdown 表格；点击「解析并预览」。
3. 核对岗位族、实际词条数及规则，再点击确认保存。预览不写数据库；相同岗位族 ID 更新，其余岗位族保留。
4. 在「岗位族管理」核对默认代表词；编辑路线、代表词、优先级、别名和独立 JD/资格/风险词。停用岗位族不删除历史计划。
5. 在「检索规划」选择路线或具体岗位族、城市、平台，设置页数、详情次数和时间规划值，再预览。
6. 预览仅展开代表词；相同搜索词＋城市＋平台合并并保留多个岗位族关联。额度不足的组合明确列入未覆盖范围，别名保持待探索。
7. 保存计划后逐条点击「准备检索」。程序建立并复用该动作的采集批次，切换到收件箱；检查连接、预览并确认后才启动平台检索。
8. 检索结果沿用收件箱的筛选、人工核对及入库流程。重新打开计划能看到已准备批次和本地已记录的采集状态；在收件箱刷新可获取最新平台状态。

计划保存词库版本、用户条件、岗位族和分配快照；以后编辑词库不会改写旧计划。重复准备同一个动作返回同一批次，不自动启动另一次采集。界面提示词库版本冲突时，刷新后重新预览，避免覆盖另一窗口的修改。

## 实际数据与限制

内置模板仅整理用户已提供的表格：40 个岗位族（P0/P1/P2/P3 为 11/13/10/6）、171 个不同搜索词、207 个 JD 特征项（含岗位族局部项与通用项，允许跨岗位族重复）、2 个通用资格条件和 6 个通用风险规则。原材料所述 313 词完整下载文件未提供，不能视作已导入。路线按编号前缀初步分组，可人工调整；P3「主要用途」是职业说明，不转为 JD 特征。

此阶段支持人工逐条执行计划，尚无自动连续执行、跨轮轮转、别名自适应扩展、列表与详情分段、跨轮缓存调度。额度目前用于分配和预览，不是计划级累计消费保证；时间值不会自动停止整个计划。实习僧单次详情尝试上限按分配值传递，失败/过滤也计入其尝试上限；BOSS 尚无可核验的严格详情成本约束。手工调整采集页参数会改变本次采集范围。

## 文件格式

JSON 为岗位族数组，或包含 `families`、`global_jd_features`、`global_qualification`、`global_risk` 的对象。岗位族字段：`id`、`route`、`name`、`priority`（P0–P3）、`representative`、`aliases`、`jd_features`、`qualification`、`risk`、`enabled`。

CSV 使用相同英文列名；`id,route,name,representative` 必填。多词字段使用顿号或分号分隔，含分隔字符的 CSV 单元格按 CSV 规则加引号。JSON 多词字段使用数组。

代表搜索词最多 120 字，不包含逗号、分号或换行；城市最多 64 字，单独列出。非城市标签如「不限」「远程」不能作为城市查询；「全国」目前仅支持明确选择实习僧。每次导入最多 500 个岗位族、30 万字符，文件最多 2 MB。超出规模应拆分导入。

完整 SQLite 备份包含词库和计划；JSON 导出新增 `planner_library`、`planner_families`、`planner_plans`、`planner_actions` 四张表。

## 本轮检查与用户流程回顾

- 158 项后端测试通过，覆盖版本冲突、计划快照、查询去重、额度边界、并发准备复用、解析错误、实习僧详情上限及老批次打开。
- 隔离数据库浏览器流程通过：V1 加载、预览、保存40族、选择2族×2城市、2页预算仅生成2项且显示2项未覆盖、保存及重载恢复、准备同一动作仅生成1个批次、详情分配2次传入采集页。平台连接状态使用模拟响应，未发起真实招聘搜索。
- 并发点击不同准备动作时，仅处理首个请求；720px 窗口横向不溢出。
- 从用户现有数据库制作只读快照后迁移到 schema10，原2个批次/15条资料保留，完整性及外键检查通过；检查未改写用户数据库。
- 改善了异步预览失效、词库并发编辑覆盖、代表词长度、Markdown 特征遗漏、查询准备重复/混用和百条之外老批次打开。用户仍需在采集页确认本次参数；下一阶段应将运行预算与计划关联并由连接器回执结算，减少当前人工跨页面操作。
