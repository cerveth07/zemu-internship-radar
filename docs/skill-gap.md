# 能力差距工作台（Schema v20）

本页是原「能力情报」与「JD 需求画像」的统一日常入口。原「JD 需求画像」仍保留为「高级 JD 统计」，原我的能力与经历管理仍可从本页进入。旧 API、批次和岗位原文不删除。

## 日常流程

1. 默认只统计重点关注 High 和适度关注 Medium 的岗位；切换「全部已收录岗位」可以扩大范围，也可以继续按岗位方向及企业档位筛选。
2. 点击 **导入 AI 结果**，选择 JSON 文件：
   - `{"package_id":"…","requirements":[…]}`：AI 从 JD 原文提取的候选要求，先核对原文/批次，确认后以**待核候选**展示；
   - `{"batch_id":"…","decisions":[…]}` 或 `{"results":[…]}`：已导出批次的 AI 复核结论，通过后以 **AI 复核** 显示；
   - 后端继续执行原批次 ID、JD 原文、版本、全量覆盖校验。不支持把任意无来源的技能总结直接入库。
3. 点击每项能力后的状态菜单：**待评估、已满足、部分满足、未满足**。这是用户的个人判断，不等同于 AI 复核或 JD 审核。状态在本地 SQLite 的 `personal_skill_status` 表中单独保存。
4. 展开能力后查看 JD 原文示例、对应岗位、我的能力与经历和已有学习任务。可直接从该能力创建参考资料或学习任务。
5. 需查看详细分组、组合要求和别名映射时，点击「高级 JD 统计」。

## 计数规则

同一个筛选岗位的同一能力只计一次，优先级依次为：**人工已确认 JD 要求 ＞ 当前有效 AI 复核要求 ＞ 当前待核候选**。去重后的岗位数用于条形图；原文摘录始终保留来源标签。工作职责、任职资格、组合条件不能冒充独立技能。JD 变化后失效的原文要求不纳入新统计；已经保存的个人状态不会因此自动改变或删除。

**注意：候选出现频率并非技能重要性，更不代表个人是否掌握。** 未核候选可能把职责误读为要求；默认允许展示以帮助尽早识别需求，但可取消勾选「包含待核候选」仅看有效已核要求。各档位相互区分，不生成不透明的单一匹配分数。

## 数据变更与回退

Schema 19 → 20 仅新增 `personal_skill_status` 表。所有原有 JD、人工审核、AI 复核、企业数据、投递及学习记录保持不变。更新桌面版前建议在「数据与集成」备份 SQLite。本次未引入额外 AI API、向量数据库或新的抓取系统。
