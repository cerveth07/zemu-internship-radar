# 下一阶段：岗位语义分类与自适应检索

状态：v0.10.0 已实现 P0-A：词库导入、岗位族管理、代表词规划、计划快照与逐条准备采集。操作见 [关键词与检索规划](keyword-planner.md)。P0-B 已在实习僧接入分段采集、详情续补、缓存/身份/命中/成本记录及计划额度约束，见 [分段采集](staged-collection.md)。BOSS 成本约束、未访问列表页的自动续跑、跨轮探索和自动连续执行仍按后续阶段开发。

## 目标与衡量方式

使用大词库持续发现高价值、符合个人硬性条件的新实习，积累可追溯的岗位与招聘需求变化。

记录搜索页数、实际详情读取尝试、耗时、失败原因，以及新增平台记录、已确认的新求职机会、相关程度和资格核验结果。没有人工或可靠参考资料确认的岗位标记为「待评估」，不当作无效岗位；JD 更新不算新增岗位。

「单位成本获得的有效新增」只使用已经完成资格与价值评估的记录。分别显示搜索成本和评估完成率，避免未审核的查询被错误降权。不同平台的成本单独统计；可先比较每次详情尝试、每页和每分钟的收益，不立即合成一个不透明总分。

职业路线覆盖用已探索的岗位族、搜索组合与已发现岗位分布衡量。没有平台全集，不能宣称已经测出真实召回率；「未找到」不等于岗位不存在。

## 词库与分类

职业路线 → 岗位族 → 代表词与同义词；JD 特征词、资格条件与风险规则独立管理。

- 岗位族保持稳定 ID、优先级、人工指定代表词及可按平台调整的搜索同义词；一个词可以关联多个岗位族。
- 一个岗位可以同时属于多个岗位族。分类保留命中的原文片段、规则版本和人工修订。
- 只归一化格式差异，如外围空白；不凭相近含义自动删除英文/中文别名、缩写或专业名称。
- 同义词是待探索资源，首轮只选择代表词，后续按不足、差异命中或探索额度扩展；不永久取消别名。
- 首期导入 JSON/CSV，粘贴的 Markdown 表格先生成可修订预览。校验 ID、分层、重名、别名关联和字段用途，确认后才保存。
- 以实际提供的数据计数。当前粘贴材料标注 313 个词，但没有附上完整逐词文件；不能自行补造缺失词，也不能假定已经导入 313 个词。

## 规划、预算与执行

用户选择职业路线、城市、平台和本轮预算后，规划器生成可预览的代表词组合，并保存条件和词库版本快照。未被选中的同义词保持待探索，不展开成必须全部执行的任务。

首期采用确定性规则：优先覆盖 P0/P1，同时按岗位族轮转，避免单一岗位族消耗全轮资源。保留可配置的探索份额，初始建议 20%，用于长期覆盖不足的路线、尚未测试的别名和低频新名称。

预算分别限制搜索页数、实际详情读取尝试和执行时间，向岗位族/查询分配份额。下线、重复、城市不符、解析失败的读取仍计成本；重试也消耗预算。未使用的额度可回到计划，不能由先启动的任务无限占用。

预算必须由连接器真正执行，调度器在启动前预留额度，并按实际回执结算。BOSS 与实习僧需要分别报告能力和成本；缺少精确读取计数或停止保障的采集模式不得假称支持严格的详情预算，也不能用已同步条数替代读取成本。

访问后未写回执的崩溃窗口按「结果未知」处理，预留额度不能无依据释放；先核对运行参考资料，再决定是否另计成本重试。详情动作执行前再次检查缓存，人工补详情与后台补全共用来源身份约束，避免重复访问。

P0 默认串行执行；当前每平台单任务约束继续保留。后续只有在全局额度能够事务预留、平台运行稳定时才开放受限并发。

效率设计补充见 [检索效率与成本控制](search-efficiency-design.md)：列表发现与详情读取分开规划，先按来源身份消除重复读取，再按候选价值和信息缺口分配详情额度。探索、缓存核验与重试都包含在本轮预算内，不在结束后追加隐性消耗。

任务状态明确区分待执行、运行、暂停、需人工处理、成功空结果、部分完成、失败和取消：

- 只在可靠解析了平台空结果时记录「成功空结果」；登录墙、验证码、页面结构变化不是零结果。
- 验证或访问限制暂停当前平台，不自动循环重试；其他模式的资料仍可导入。
- 瞬时故障允许有限次数重试，保存错误及耗费，避免重复启动未知状态的任务。
- 重启后恢复计划、已完成组合和同步游标；先查明运行任务的状态，不重复执行已完成查询。
- 停止计划意味着不再启动新查询，同时请求停止其确实拥有的活动任务；保存已获得的参考资料。

## 规则式自适应

| 反馈 | 初期动作 | 必须避免的误判 |
| --- | --- | --- |
| 已确认有效新增较多 | 下一轮增加少量页深或额度 | 未审核候选数量不能冒充有效新增 |
| 重复高且边际新增低 | 降低频率，暂缓高度重合的别名 | 别名以后仍可获得探索额度 |
| 大量明确不相关结果 | 尝试更具体的代表词 | 数据解析错误不能归因于关键词差 |
| 可靠的空结果 | 延长重试间隔 | 失败或受限不能记为零结果 |
| 某路线长期探索不足 | 分配探索额度 | 少搜到岗位不证明这个领域没有需求 |

保存每次调整的原因、依据和规则版本，允许人工覆盖。历史样本不足时使用固定轮转和保留探索额度，P2 才引入自动学习预算或关键词发现。

首次发现归属受执行顺序影响，不能单独作为查询优劣依据；补充边际独有命中并轮换可比查询的执行顺序。人工审核存在选择偏差，已审核有效率应展示样本数和来源，未知或未执行查询不记零收益。预算按当前发现、详情、审核或新鲜度瓶颈分配，未覆盖范围明确展示并跨轮轮转。

## 岗位身份与历史

- 同平台＋岗位 ID 是招聘记录身份；没有 ID 时使用该平台经过规则验证的来源链接作为回退，保留原始链接。
- 同一招聘记录再次命中更新最后发现时间，追加本次查询、岗位族、计划与观察记录。保留 JD 版本和变化内容，不覆盖过去的参考资料。
- 跨平台根据公司、团队、城市、职责、发布时间等形成疑似关联，由人工确认后关联到同一求职机会；每个来源仍独立保存。
- 相同公司和标题的不同团队、批次或资格要求可以是独立岗位，禁止标题相似即自动合并。
- 未再次搜到只表示本次未命中。只有页面明确下线或人工核验才改变来源开放状态。
- 区分「新增来源记录」与「新增求职机会」。发现归属和每个搜索词的命中记录都保留，不因去重丢失别名的贡献参考资料。

现有 `jobs`、`job_sources`、`job_history`、重复审核及 `capture_search_runs/results` 是复用基础；需要补齐来源身份、逐次观察和查询命中关联，不能假定目前已经具备完整身份管理。

## 资格优先，价值与匹配独立

先核验实习类型、学历、专业、毕业时间、到岗时间、期限和出勤条件，结果分为符合、明确不符、信息不足。条件与用户资料均需有依据；信息不足进入待核验，不自动当作不符合。

明确不符合硬性条件的岗位进入观察范围，保留参考资料与职业价值评价，不进入当前优先投递队列。观察范围复用同一个岗位库，以视图和评估状态区分，避免另建一套孤立数据库。

职业价值和个人匹配分别展示评分依据与原文，不以技术关键词数量替代硬性资格核验。未知项不填零分，也不输出伪精确的 offer 概率。技术型 FDE、方法设计型 Eval 与销售实施/人工执行工作按具体职责区分，风险词不做全局单词黑名单。

现有 ChatGPT 分析数据桥可承接人工审核的语义结论；首期无需新增强制模型 API 或要求采集阶段调用 AI。

## 采集模式与统一入库

支持自动只读检索、浏览器辅助、文本导入、截图/OCR 和手工补录。按连接器实际能力选择模式，自动采集受限时展示人工切换入口，不隐藏失败原因。

所有模式进入现有采集收件箱，保留平台、原始链接/ID、获取时间、采集方式、原始参考资料、OCR/解析草稿及计划关联。人工确认后进入统一岗位库。人工/OCR 导入不伪造平台搜索命中；不计入某个词的自动检索效果，除非存在实际可核验的任务关联。

## 实施顺序与验收

| 阶段 | 范围 | 验收结果 |
| --- | --- | --- |
| P0-A | 词库导入预览、职业路线/岗位族/别名管理、代表词规划 | 大词库可保存和选择；预览只生成选中的代表词组合，剩余别名保持待探索 |
| P0-B | 列表/详情分段队列、全局/岗位族额度、来源身份与缓存、暂停续跑和命中记录 | 相同来源 ID 同轮只取一次详情；新命中可复用有时间标记的缓存；未知字段不提前排除；恢复不重跑完成动作；探索和核验额度均在预算内 |
| P0-C | 自动失败转浏览器辅助/文本/OCR/手录，并保留关联 | 平台不可用不影响收集；已有资料和原文不丢失，不伪造成功任务 |
| P1-A | 多标签 JD 分类、硬性资格核验、价值/匹配双维度与三个工作视图 | 高价值但不满足资格的岗位进入观察；未知条件进入待核验；每条建议可定位参考资料 |
| P1-B | 查询收益统计、可解释的代表词/别名扩展与降频 | 未审核不被当无效；空结果与受限区别处理；重复率高仍保留探索机会 |
| P2 | 自动预算优化、候选新词发现、招聘需求变化分析 | 在已有历史和反馈上评估增益、偏差及覆盖；所有调整可解释、可撤回 |

首期不要求一次实现全部 P1/P2。每个阶段都应覆盖停止后恢复、重复命中、JD 变更、资格不符/未知、平台受限和多模式导入这些实际使用案例。
