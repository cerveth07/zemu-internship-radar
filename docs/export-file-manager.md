# Windows 桌面版导出文件的位置与管理

## 保存在哪里？

桌面窗口首次导出时会在 Windows 的「下载」中使用「择木」文件夹。如果你之前用过旧版，且还没有「择木」文件夹，应用会继续使用已有的「实习雷达」或「AI实习雷达」文件夹。你手动选过的保存位置优先。

在「数据与集成 → 导出文件位置」可以看到具体目录。按「打开导出文件夹」启动资源管理器，按「更改保存位置」使用 Windows 原生选择文件夹窗口。以后新文件写入新目录，之前导出的文件不会被移动或删除。

**普通浏览器版**：继续由浏览器处理保存路径和另存为设置；网页无法准确知道文件最终保存在哪里。导出完成会提示按 **Ctrl+J** 查看下载历史。不能承诺能从网页直接打开某个实际下载文件。

## 导出完成后

桌面版显示轻量浮层：真实文件名、实际完整保存路径、「打开文件所在位置」（Explorer 自动选中该文件）、「复制路径」及「关闭」。此提醒不会自动弹出资源管理器。

「数据与集成」列出最近 **10** 个导出文件，含文件名、导出时间、大小、路径和定位按钮。记录最多保存 30 条在用户配置目录中的 `export-history.json`；记录仅含文件元数据，不会保存导出的 JSON、简历或 JD 内容。如果用户把文件移走、删除，记录显示「文件已移动或删除」，不会假装仍可定位。

默认使用原始文件名；如果目标目录有同名文件，则生成 ` (2)`、` (3)` 等后缀，绝不覆盖已有文件。

## 哪些导出走统一保存逻辑？

- 岗位库与企业观察库：JSON/ZIP
- 求职分析数据包：JSON/ZIP（含完整或精简 JD）
- ChatGPT 分析工作台：历史分析包 JSON/Markdown、职业分析提示词、JD 提取提示词
- JD 需求画像：统计 JSON
- 数据与集成：SQLite 数据库备份、完整 JSON 备份、CSV 示例
- 采集收件箱：带截图的完整 ZIP 备份
- 关键词规划：模板 JSON

软件**不会**把用户已通过浏览器下载的旧文件自动搬进新目录；请到原来的浏览器下载记录中查找。

## 实现和安全

桌面版借助 pywebview 的 Python `js_api` 将导出请求交由本机处理。针对服务端 JSON/ZIP/SQLite，Python 从桌面自己启动的本地 HTTP 服务获取内容并流式写入磁盘，避免把上百 MB 的 ZIP 整体复制进 WebView2 的 JS/Python 桥。对于仅在页面生成的 Markdown 或小型 JSON，则由桌面桥直接接收文本。

原生桥**只允许白名单内的本地 GET/POST 导出接口**，不接受前端任意 URL；文件名不能包含路径、危险扩展名或 Windows 保留名称。所有记录存放在本机用户目录，下载失败后清理半成品，不会悄悄覆盖旧文件或修改岗位数据库。

导出路径与近期记录分别保存在：
`%LOCALAPPDATA%\\InternshipRadarPrivateRC\\export-settings.json` 和
`%LOCALAPPDATA%\\InternshipRadarPrivateRC\\export-history.json`。

## 验收重点

1. 从 Windows EXE 运行一项 JSON 导出，确认文件真的存在，点击「打开文件所在位置」可在资源管理器中选中该文件。
2. 导出相同名称两次，确认两个文件均存在且内容没有相互覆盖。
3. 修改默认导出目录，再导出一次：新文件保存到新目录，旧记录仍可定位之前的文件。
4. 删除一条测试导出文件后，重新进入「数据与集成」，该记录应该显示文件已移动或删除。
5. 导出多批次 ZIP 与 SQLite 备份，确认所得文件可正常打开，数据未截断。
6. 使用普通浏览器访问同一服务，确认仍由浏览器下载并明确说明无法获取实际路径。
7. 关闭重启 EXE，确认设置和近期记录仍在，岗位数据库未被修改。

本功能合并源码不等于完成 Windows EXE 实机验收。若本机 EXE 尚未重新构建，旧 EXE 不会自动获得此功能。
