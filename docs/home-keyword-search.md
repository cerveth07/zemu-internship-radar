# 首页关键词检索

## 使用方式

首页的“输入关键词，寻找实习岗位”是主入口。输入岗位关键词（每行一个或用逗号分隔，也可从岗位词库勾选），选择一个或多个城市和平台，点击“开始检索”。应用先检查输入与采集环境，就绪后立即开始，进度和取得的岗位自动回到首页。

BOSS 默认使用“独立采集窗口”。应用打开 Windows 本机的 Chrome 或 Edge，首次需在专属窗口登录 BOSS。也可选择“使用当前 Chrome”，通过开源 [leeguooooo/chrome-use](https://github.com/leeguooooo/chrome-use) 的 CLI 和扩展在后台复用现有登录。需要人工操作时，在任务窗口或标签处理，再回首页点击“继续检索”。访问受限或操作频繁时本轮停止。

采集结果先保存在收件箱，点击“核对本次结果”检查后入库。首页显示前 30 条结果，完整结果在对应收件箱批次查看。停止、网络错误和部分详情读取失败不删除已经保存的结果。

### 当前 Chrome 的一次性连接

1. 按 [Chrome Use 官方 Windows 安装说明](https://chrome-use.leeguoo.com/)安装 CLI，并安装 [Chrome 商店扩展](https://chromewebstore.google.com/detail/chrome-use/knfcmbamhjmaonkfnjhldjedeobeafmk)。这是开源项目，不是 ChatGPT／Codex 内置的 Chrome Use 插件。
2. 运行一次 `chrome-use extension install` 注册本地连接；保持安装扩展的 Chrome 配置窗口打开，并在其中登录 BOSS。应用不会自动重启 Chrome、关闭调试提示或代替用户处理扩展权限。
3. 回到首页选择“使用当前 Chrome”并开始检索。预检仅运行只读 `status`，不会打开浏览器窗口或检索标签。连接失败会提示具体处理步骤；不会静默改用独立窗口。

当前适配器按上游 `v1.5.281` 的 CLI JSON 协议实现。预检要求 CLI 为 `1.5.281` 或更新的 `1.5.x`、扩展为 `0.5.105` 或更新的 `0.5.x`、正在运行的本地连接组件版本与 CLI 一致，且只有一个配置明确连接。超过这一版本范围须重新验证接口。商店扩展可能自行更新，不能把安装时版本当作永久锁定。应用调用期间禁用 CLI 自动升级与自动开窗重连；不更改用户已有的站点权限／审批策略。

应用从官方默认安装目录或 `PATH` 查找 CLI。开发时可用绝对路径环境变量 `RADAR_CHROME_USE_PATH` 指向便携安装。桌面包内置本应用的适配器及 Node，不包含 Chrome Use CLI 或扩展，也不会在预检时下载、安装第三方软件。

“独立采集窗口”使用专属登录目录，无需 Chrome Use、WSL 或 BossHunter。首次创建窗口可能进入前台。应用会记住用户选择的模式。

### 标签回收与焦点

列表和详情顺序处理，复用一张任务标签，不为每个岗位新开标签。Chrome Use 使用 `radar-<任务标识>` 作为专属会话，命令固定配置和标签 ID，不接管个人已有标签。每隔至少 30 秒，在两次访问之间检查一次闲置标签；仅回收会话明确标记为 `created`、闲置至少 30 秒且未用于当前访问的标签。登录／验证码、未知来源弹窗和当前检索标签保留到需要它们的阶段结束；人工等待期间不做回收。

完成、停止或失败后尝试关闭本任务标签，再保存实际清理结果。普通标签关闭失败后还会尝试该会话的关闭；只有收到确认才能显示已回收。连接中断导致无法确认时，结果仍保留，首页提醒手工检查“择木”标签组。不会使用 `Browser.close`、进程结束、强制关闭、全局标签清扫或接管其它会话来清理当前 Chrome。

后台加载仍受目标网页影响；没有推进的列表不会标作成功翻页。网页自行弹窗或浏览器系统提示仍可能干扰焦点，所以“代码不主动置前”需要和真实 Windows 上的表现分开验收。

## 从岗位词库选择

点击“从岗位词库选择”，按方向勾选岗位族，会填入它们的代表词。勾选“同时加入别名”也会填入别名。弹窗显示当前城市和页数对应的关键词上限。默认展示内置 AI 方向示例词库，也可在“关键词与检索规划”导入任意行业的自定义词库。直接输入关键词也能检索。

“关键词与检索规划”保存计划后，每一项都可以点“在首页检索”，把该项的搜索词、城市、平台和页数带回首页，确认后再开始。

## 关键词文件

点击首页“下载 CSV 模板”，用支持 UTF-8 CSV 的工具编辑；保留表头 `keyword`，每行填一个关键词。例如：

```csv
keyword
产品运营实习
财务分析实习
机械设计实习
```

也可导入 UTF-8 TXT，不带表头，每行一个关键词。支持 UTF-8 BOM。短语内的空格保留，首尾空格和空行忽略，重复关键词合并。文件最大 64 KiB，非 UTF-8、错误表头、多列 CSV 或超出检索范围都会显示错误，并保留原来的输入。

导入成功会替换表单中的关键词；选择文件本身不会发起检索。接口兼容旧版单个 `city` 字段；新版首页发送 `cities` 列表。`.xlsx` 不是导入格式，使用 Excel 时请另存为“CSV UTF-8”。

## 本轮范围

| 项目 | 范围 |
| --- | --- |
| 平台 | BOSS 直聘或实习僧，每次一个 |
| 关键词 | 1–9 个不同关键词，每个最多 80 字；换行、逗号、顿号或分号分隔 |
| 城市 | 1–9 个，默认北京。常用城市点选，其他城市可以回车添加，也会在提交时纳入。粘贴“北京，上海”会自动拆分。BOSS 使用内置城市表校验 |
| 关键词 × 城市 | 每个关键词在每个城市各检索一遍，最多 9 组 |
| 岗位类型 | 实习 |
| 每关键词列表页数 | 1–3 页，默认 1 页 |
| 总列表页数 | 关键词 × 城市 × 每词页数，不超过 12 页 |
| 详情读取次数 | 1–60 次，默认 30 次 |

范围上限是本轮访问预算，不是平台全部岗位数，也不保证取得相同数量的岗位。已关闭岗位、非实习岗位、城市不符以及页面读取失败都会影响实际结果。平台字体导致薪资无法可靠读取时留空并标记，供查看原始页面核对。

## 任务与兼容

- 同一次启动请求使用持久化请求标识；重复点击、响应丢失后的重试不会重复创建任务。明确发起下一轮会取得新的请求标识。
- 首页重开会恢复最近任务。查询状态的 GET 接口只读；任务刷新和结果同步通过 POST 执行。
- 等待登录或验证时，继续操作作用于原任务。停止后如需再次采集，重新开始一轮。
- 新的首页 BOSS 任务记录 `connector: native` 和 `browser_mode: chrome_use` 或 `managed`，同批重试沿用记录的模式。历史原生任务缺少 `browser_mode` 时按 `managed` 解释；没有原生 connector 标记的历史任务仍归 BossHunter。不会根据当前设置重新解释旧任务的归属。
- 沿用现有采集批次、任务、候选、访问回执和收件箱表，不新建一套岗位数据。结果核对规则和已有岗位去重流程保持统一。
- 完整备份只带上数据库归属明确的本地结果快照，不带浏览器 profile、Cookies、运行配置或日志。恢复后未完成任务按中断处理，不自动重新登录或发起检索。

## 开发验证

后端测试 `tests/test_home_search.py` 覆盖关键词校验、请求幂等、自动同步、部分失败保留结果、登录继续与停止。前端测试 `tests/test_home_search_frontend.py` 运行实际脚本，检查文件解析、浏览器模式、单击启动、错误保留输入和结果、任务恢复及安全渲染。`tests/test_boss_native.py` 与 `tools/test_boss_runner.mjs` 检查连接器归属、恢复、页面解析、单页复用、后台回收及人工继续协议。`tools/test_chrome_use_browser.mjs` 用上游协议夹具检查后台命令、固定标签、所有权保护、UTF-8 标准输入、超时与关闭失败；这些是接口测试，不是真实扩展验收。

这些隔离测试不能替代真实 Windows 和 BOSS 页面验收。发布前应在完整桌面包中完成：

1. 在未安装 Chrome Use 的 Windows 10/11 上，从首页使用默认模式打开 Chrome/Edge 专属窗口。另测已连接 Chrome Use 时的可选模式，确认只新增后台任务标签并保持原有标签及焦点。
2. 首次登录、登录过期或验证码出现时，首页保留任务与结果；用户在浏览器完成操作后，点击继续可在同一任务中采集。
3. CSV/TXT 导入、模板下载、重复关键词和非法文件提示符合本文约定。
4. 实际列表和岗位详情满足关键词、城市、实习条件；多页查询不反复读取同一批结果。
5. 停止、关闭应用后重开、网络中断及再次检索可解释当前状态，已有结果可从收件箱核对。
6. 完整备份恢复后保留结果，备份中没有浏览器登录资料；原有 BossHunter 和实习僧任务仍由原连接器处理。
7. 等待人工登录／验证时不清理正在使用的页面；任务结束只关闭任务标签，个人和其它会话标签保留。断开扩展、手动关闭任务标签、CLI 超时和清理失败时，已有结果可查看，提示与真实情况一致。
