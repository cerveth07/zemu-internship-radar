# 数据恢复与分析一致性

## 备份恢复

完整 ZIP 备份现在包含数据库、招聘截图，以及数据库引用的实习僧 `result.json` 快照。
不会备份浏览器进程、运行配置或日志。恢复必须在关闭应用后执行。

恢复的运行任务会标记为中断，保留已经采集的结果，允许同步和重新检索。
旧 ZIP / SQLite 备份没有任务快照时，已同步的收件箱资料仍保留；尚未同步的结果无法凭空恢复。
对缺失快照的旧任务，刷新、停止或新建检索会解除旧记录的阻塞；仍有已知运行进程时不会强行解除。
快照归属不一致会拒绝恢复。目标目录存在同名但不同内容的快照时，请恢复到新的空目录，避免混入另一版本。

## 优先级结果

从岗位库导出的 JSON 已有 `package_id`。交给 GPT 后，返回以下对象：

```json
{
  "package_id": "原导出文件的批次 ID",
  "priorities": [
    {"job_id": 123, "priority": "medium", "reason": "具体依据"}
  ]
}
```

`priority` 可取 `high`、`medium`、`low`、`skip`、`unrated`。
导入 API 使用同一批次的 `rows` 字段；界面会将 `priorities` 转成 `rows`。
预览和正式写入都会检查岗位是否属于该包，以及资料和优先级是否发生变化。
同一文件有任一冲突时整份不写入；请重新导出评价，不会强行覆盖后续人工修改。
完全相同且未发生后续变化的结果可以重复导入，不重复增加历史记录。
无批次的旧优先级数组不再写入，不能用新批次 ID 包装旧结果绕过版本检查。

## JD 要求与人工技能

新导出包的 JD 提取只比较 `jd_text` 与 `eligibility`；调整优先级、备注或核验状态不再导致返工。
旧 JD 提取批次可复用已有原文指纹；没有原文指纹的旧通用分析包仍保留原来的完整版本校验，
若已失效需重新导出一次。数据库升级至 schema 21，仅新增原文指纹字段，不重写历史快照。

人工技能确认有独立来源，直接进入能力差距。仅有普通导入标签、没有人工确认记录、
没有原文参考资料的技能不进入统计。新确认记录绑定当前 JD / 资格原文版本；历史确认则校验当前原文参考资料。
与 JD 要求重合时，同岗位同技能只计一次，已确认 JD 要求优先；清空人工技能会移除对应贡献。
个人掌握状态仍由用户设置。

采集核对表单新增发布日期、截止日期，支持保存草稿和手动修正；入库与重复审核保留这两个字段。
同一来源仅日期变化也进入人工审核，不自动覆盖已有岗位。
