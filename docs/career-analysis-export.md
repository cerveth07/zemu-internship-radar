# P3.1–P3.2｜求职分析 JSON 数据包（手动交给 AI 助手）

## 功能边界

择木只整理、筛选、导出数据；**不会自动访问 AI 助手、评价个人能力、推荐课程或直接修改岗位事实**。本阶段实现两种导出模式和可选择的我的能力与经历。专用提示词模板和强化结果回收（P3.3）下一阶段完成。

## 使用流程

1. 在「岗位库」设置方向、档位、优先级、状态、城市或搜索词，得到目标岗位列表。
2. 进入「AI 分析工作台」，在顶部「00 · 求职分析数据包」选择**精简版**或**完整版**、分析目标。
3. 个人经历默认全不选。如需分析个人能力差距，逐条勾选「我的能力与经历」，阅读完整经历描述和来源；生成前再确认。
4. 点击「生成并下载求职分析 JSON」。数据量不大时直接下载单个 JSON；较大时下载 ZIP，内含 `manifest.json` 和分批编号的 `career-*.json`。
5. 自行检查文件并上传 AI 助手网页端。每个批次都含原岗位 ID、`package_id` 和明确的数据覆盖提示。
6. 现有「导回 AI 助手结论」已支持该数据包的 `package_id`，前提是按目前 `findings` 结构填写；未来 P3.3 再补专用提示词和个人经历/要求版本变化核验。

## 数据包内容

```
schema: ai-internship-radar-career-export-v1
package_id: 本批 UUID
export_metadata: export_id / batch / batch_count / mode / analysis_goal /
                 selection_total / selection_filters / generated_at_utc
coverage: 全部选中岗位数、存在已确认 JD 要求的岗位数、
          缺少已确认要求的岗位数、本批未覆盖岗位 ID
demand_statistics: 与选中岗位 ID 严格一致的 P2 统计，
                   含技能频率、确认覆盖率、分组比较、别名版本
jobs[]: 选中岗位的 ID、企业、档位、职位、方向、优先级、状态、
        城市、已确认的结构化要求和来源
personal_evidence[]: 用户显式勾选的参考资料 ID、技能、程度、项目描述和来源
privacy: 显式选中的参考资料 ID 及不导出私人备注等字段的说明
```

### 精简版（默认）

- `jobs[]` 中不含 `jd_text` 或原始 `eligibility` 全文，包含**已确认**的 JD 要求及对应原文参考资料。
- 还没有已确认要求的岗位仍然出现，`confirmed_requirements: []` 和 `requirements_coverage: no_confirmed_requirements` 表示**尚未核实**，不能理解为“该岗位没有要求”。
- 即使已有已确认要求，也不保证该岗位的全部要求已经提取完成。AI 助手必须明确标注分析覆盖局限。

### 完整版

- 在精简版基础上，逐条补充 `jd_text` 和 `eligibility` 原始全文。**任何单条 JD 都不静默截断**。
- 超大单条 JD 或最终分析包超过 3 MB 时，明确返回错误，整次导出回滚、不保存半成品。
- 大规模数据通过现有按条数/UTF-8 字节数自动分批，并带 ZIP 校验清单。

## 隐私与数据可信度

- **仅明确勾选的个人经历 ID 才会进入包**，零选择时输出空列表。
- 个人资料包括记录中的完整描述和来源 URL；即使曾在其他分析工作台打开 `include_private`，此导出也不会自动复用那个选项。
- 岗位私人备注、招聘联系人、简历版本、投递状态记录、企业私人备注均不包含在求职包中。
- 对手工选择的 `needs_check` 个人经历，原样标记其核验状态，不能当作已证实的经历。
- 企业和招聘来源等外部文本也可能涉及个人信息，上传 AI 助手前仍需自己检查。
- 统计仅基于有效的**已人工确认**要求；不因筛选改变岗位优先级、招聘核验状态或个人资料。
- 一个导出操作在 SQLite 同一事务内读取数据并保存快照，选中岗位 ID 缺失或个人经历 ID 失效则整体失败。

## 版本追溯

为后续结果回收做准备，Schema 从 13 增加到 14，只新增 `career_export_snapshots`，不更改历史岗位、已确认要求或个人经历。每个批次保留：

- 关联到 `analysis_packages` 的 `package_id`；
- 当时导出的岗位 ID 集合、筛选条件和分析目标；
- 每个岗位**已确认结构化要求集合的哈希**；
- 每条已选个人经历内容的哈希。

SQLite **不重复保存**个人经历或大段 JD 正文，只存所需追溯 ID 与哈希。原有分析结论导入的 JD 快照检查保持有效。P3.3 才会把新增的要求与个人经历哈希纳入求职结论导回的过期核验。

## 限制与后续

- 新数据包的“求职分析任务”选项只是结构化目标标签，并不调用模型。
- P3.3：提供 3 套 AI 提示词，扩展导回时的个人经历及要求哈希核验，并与现有 `analysis_findings` 和学习任务衔接。
- P3.4：交互验收、回归、运行测试与 Windows EXE 打包；当前未完成该部分。
